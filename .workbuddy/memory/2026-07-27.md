## 强制锁屏功能
- 新增 ForceLock 模块，解决用户"切出浏览器/App 就能跳过专注"的问题
- 三层防线：
  1. beforeunload：关闭/刷新页面时弹出浏览器原生确认对话框
  2. visibilitychange + pagehide + 定时检测：任意方式切出都会被记录
  3. 返回时强制锁屏覆盖层：显示离开时长、累计次数、惩罚时间，需长按确认返回
- 惩罚机制：每次离开加时 2 分钟（最多 10 分钟），频繁逃避被标记到历史记录
- 在闹钟设置页增加「强制锁屏」开关，默认开启
- Store 新增 forceLockScreen 设置字段

## 修复悬浮窗逃逸漏洞
- 问题：用户将页面挂在悬浮窗（PiP/分屏），页面 visibilityState 仍为 visible，强制锁屏完全不触发
- 方案：三重检测替代单一 visibilitychange
  1. visibilitychange（原有）
  2. window blur/focus（新增：切 App / 悬浮窗点击其他 App 触发）
  3. 心跳漂移检测（新增：setInterval 500ms，检测执行间隔是否被浏览器节流 > 1500ms）
- 核心原理：浏览器对所有非活跃前台的标签/窗口都会节流定时器，悬浮窗也不例外
- 修复了 _wasThrottled 状态残留的竞态条件，onReturn() 中统一重置

## 悬浮窗交互超时检测（第4层防线）
- 问题：悬浮窗模式下浏览器不节流定时器，心跳漂移完全失效
- 方案：追踪用户交互（touchstart/click/scroll/mousemove/keydown）
  - 25秒无交互 → 计时器变黄警告"⚠️ 未检测到操作"
  - 35秒无交互 → 记录离开 + 暂停计时 + 显示锁屏
- 原理：悬浮窗里用户操作其他 App，不会碰 FocusGuard 页面
- 同时保留心跳漂移检测作为辅助

## v7：窗口尺寸检测替代交互超时

- 新增 window resize 检测：进入专注时记录 innerWidth/Height 基准

- 新增 document.hasFocus() 每2秒轮询（悬浮窗/分屏时可能失焦）
- 心跳漂移检测加速：500ms间隔/1500ms阈值
- 保留 visibilitychange + blur/focus + pagehide + beforeunload
- resume() 时重新记录窗口尺寸（防止锁屏后窗口变小绕过）

## v8：强化窗口尺寸检测
- 悬浮窗仍无反应：部分安卓进入悬浮窗不触发 resize 事件，且窗口缩小幅度不够大
- 修复：阈值从 60% → 80%，新增宽度/高度独立检测（单维 < 85% 即触发）
- 新增定时轮询尺寸（每 1.5 秒），不依赖 resize 事件
- 使用 window.visualViewport 获取更精确尺寸（部分安卓悬浮窗 resize 不触发但 viewport 已变）
- hasFocus 轮询加速：2s → 1s

## v9：screen.width/height 物理对比（针对安卓悬浮窗 innerWidth 不变的修复）
- 安卓悬浮窗 innerWidth/innerHeight 可能不变（浏览器仍报全屏尺寸）
- 改用 screen.width/height（始终是屏幕物理像素）做对比基准
- 同时检测 innerWidth/screenWidth、innerHeight/screenHeight、outerWidth/screenWidth、outerHeight/screenHeight
- 任一项 < 0.88 → 判定为悬浮窗
- 移除 _initWidth/_initHeight（基于初始值的对比在安卓上不可靠）

## v10：调试面板 + 多方法检测（诊断为什么悬浮窗检测不生效）

- 悬浮窗检测从 4 项扩展到 5 项：
  1. innerWidth/visualViewport.width vs screen.width（< 92%）
  2. outerWidth/outerHeight vs screen
  3. documentElement.clientWidth/clientHeight vs screen（新增）
  4. screen.availWidth/availHeight vs screen（新增）

## v11：修补致命漏洞 — 记录初始 screen 尺寸做对比
- 问题根源确认：用户安卓浏览器在悬浮窗模式下**等比缩放 screen.width/height**，导致 innerWidth/screenWidth 比值永远 ~1.0
- 修复：在页面加载时记录 `_initScreenW` / `_initScreenH`（真实全屏尺寸），之后所有对比都用这个初始值
- 最关键的新检测：当前 `screen.width` 是否与初始值不同（差 > 20px），考虑横竖屏切换不误判
- 调试面板同步显示 screen_now 和 screen_init 两行，方便验证

## v12：稳定性学习 — 自动接受新屏幕基准
- 问题：用户安卓浏览器进过悬浮窗后 screen.width 永久不回退，resume 后一直检测为悬浮窗
- 方案：resume 后启动"稳定性学习模式"
  - 追踪 screen 尺寸是否连续 3 次（4.5 秒）不变
  - 如果稳定 → 自动将当前尺寸接受为新基准 → 检测恢复绿色
  - 如果中途恢复正常 → 立即接受并退出学习
  - 学习期间不触发浮窗锁屏
- 调试面板新增"学习新基准:N/3"状态显示

## v13：状态机重构 — normal/locked 双状态 + 自动恢复
- 问题：之前所有版本都有一个致命缺陷 — 锁屏后心跳不停，`_isFloatingWindow()` 返回 true 永久不变，导致无限循环重新锁屏
- 根本原因：用户的安卓浏览器进过悬浮窗后 screen.width 永久不回退，固定基准对比永远失效
- 全新方案：状态机模式
  - **normal**：追踪 innerWidth/Height，缩到基准的 88% → 锁定（连续 2 次确认）
  - **locked**：停止悬浮窗检测，仅监测尺寸是否放大（相比锁屏时 > 8%）→ 连续 2 次确认 → 自动恢复
  - blur/visibility 触发锁屏也同步设为 locked 状态，确保自动恢复同样生效
  - 锁屏通过 overlay class 判断而非 leaveStartTime，彻底消除竞态条件
- `_doLock()`：尺寸检测直接锁屏，不经 onLeave/onReturn（避免 2 秒阈值拦截）
- `_autoResume()`：检测到放大后自动解锁 + 应用惩罚 + toast 通知
- 手动 resume()：直接接受当前尺寸为新基准，回到 normal
- 调试面板同步显示状态机信息：状态、基准、当前尺寸、计数

## v13b：修复手动 resume 后第二次悬浮窗不检测的 bug
- 问题：手动 resume 时 _baselineW/H 被更新为小窗口尺寸，第二次开悬浮窗尺寸没变化 → 检测不到
- 根本原因：resume() 把缩小检测的基准污染了
- 修复：拆分两个尺寸变量
  - `_fullW/H`：真正全屏基准，页面加载时记录，仅在 `_autoResume()` 时更新（尺寸真的放大了）
  - `_baselineW/H`：当前跟踪用尺寸，用于平滑跟随，但不参与缩小对比
- `resume()` 不碰 `_fullW/H`，缩小检测始终对比 `_fullW/H` → 手动恢复后第二次悬浮窗仍能被检测

## v13c：修复切回全屏后无法自动恢复的 bug
- 致命 bug：`_onResize()` 每次 resize 都重置 `_growCount = 0`，切回全屏时浏览器连续触发多个 resize 事件，导致 `_growCount` 在 0→1→0→1 之间震荡，永远到不了 2
- 修复1：`locked` 模式不再重置 `_growCount`，由 `_checkSize` 自己管理（无增长时重置）
- 修复2：新增绝对检测路径 — locked 时如果 `curW >= _fullW * 0.95`，直接 `_autoResume()`，不依赖相对增长比例
- 双路径保障：绝对检测（1 次心跳，~1.5s）+ 相对增长（2 次确认，~3s）

## v13d：focus/visibility 事件触发即时恢复检测
- 核心 bug：`_doLock()` 不设 `leaveStartTime`，导致 `onReturn()` 看到 null 直接跳过，focus/visibility 恢复事件完全无法触发恢复检测
- 修复：focus 和 visibilitychange (visible) 事件 → 调用 `onReturn()` + 新方法 `_checkRecovery()`
- `_checkRecovery()`：locked 状态时立即检测当前尺寸是否 ≥ 全屏基准的 90%，是则 `_autoResume()`
- 绝对检测阈值统一降到 0.90（从 0.95），更宽容
- 调试面板 locked 状态新增全屏基准显示，方便定位问题

## v13e：screen.width 追踪 + 屏幕中央大号诊断面板
- 新增 `_fullScreenW/H`：页面加载时记录 screen.width/height，锁屏时记录 `_lockScreenW/H`
- 三条恢复路径（任一命中即恢复）：① screen.width 恢复到 95% ② innerWidth 恢复到 90% ③ innerWidth 相比锁屏时放大 8%
- 屏幕中央大号诊断面板：锁屏后 focus/visibility 返回时显示，列出 inner/screen 当前值和比率，标注达标/未达标
- 用户可以直接看到"inner比率: 0.85/0.85 → ❌未达标"这类信息，精准定位问题
